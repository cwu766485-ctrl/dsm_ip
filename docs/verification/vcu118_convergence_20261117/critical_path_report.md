# VCU118 critical path convergence

Status: **FAIL / BLOCKED**. These are OOC implementations of a frontend product proxy, not a physically integrated Full Top. No timing exception was added. PPA uses Vivado 2026.1 build 6511674, `xcvu9p-flga2104-2L-e`, centered cubic ×2, XPM FIFO, programmable DPD configured identity, and clocks 218.75/125/100 MHz. Vivado rounds the core period to 4.571 ns. Source SHA and complete constraints are in each run manifest; the common Tcl SHA-256 is `12315c97539a62d8ed429b8a6c7898111c520397414cbe7dc7331cca80010226`. Provisional 0.2 ns I/O budgets and absent OOC clock/port physical placement do not establish full-system timing.

The optimized EF1 case's worst path is `cfg_mailbox_q_reg[334]/C` (100 MHz AXI-Lite) to `cfg_pending_core_reg[334]/D` (core), WNS -0.363 ns, data delay 0.355 ns. The timing engine compares edges at 2930.000 and 2930.011 ns, a requirement of only 0.011 ns; this is an unexpanded clock-domain crossing. Its 0.079 ns cell delay alone exceeds that modeled requirement. Replacing logic or relocating this pair cannot reasonably meet that edge requirement. The bundled-data handshake holds its source while requested; a scoped source-domain formal assertion passed but does not prove metastability, reset during traffic or physical bus delay/skew. Physical CDC contract and an implementation-supported constraint methodology must be reviewed before interpreting this path; an arbitrary false path or multicycle path would conceal a real verification obligation. Optimized EF1 core-clock WNS +0.075 ns does not make overall timing pass. Worst-20 evidence: `../thermo5_vcu118_cubic_optimization/runs/optimized_ppa_ef1_01/ef1/setup_worst20.rpt`.

EF2's actual routed worst path is pre-DSM FIFO `data_q_mem_reg[0][15]` to `err1_q_q_reg[4]`, core-to-core WNS -97.149 ns, delay 101.701 ns, 409 levels including 190 CARRY8. The unrolled 32-sample feedback is a real one-cycle dependency. No exception is appropriate. A two-sample exact pair-lookahead candidate has simulation and bounded formal evidence but no routed PPA and no proof of the complete 32-sample integrated system. A parallel architecture must preserve saturation, state update order and every sample's output; combining a few independently verified sample transformations is not by itself a whole-core proof.

See `ppa_matrix.csv` for actual setup/hold, utilization and power; the implementation logs and `setup_worst20.rpt` / `hold_worst20.rpt` are in each indicated run directory. Power is vectorless and its reset activity warning remains applicable.

## Full 32-lane EF2 equivalence attempt

`dv/uvm/formal/thermo5_ef2_32lane_equiv_harness.sv` instantiates the baseline and pair-lookahead cores at W=16 and CHANNELS=32. `runs/ef2_32lane_formal_04/` used VC Formal V-2023.12-SP2 with zero black boxes, one clock, a declared active-low reset, 5-minute total engine limit and 2 GB configured memory. Of seven assertions, ready, valid and candidate arithmetic bounds proved; no-wrap, output data, all quantizers and state equivalence were inconclusive. Four handshake covers were reached. This is not a full-width bit-true proof. Reset setup checking was disabled in the proof setup and must be independently reviewed. Attempt 03 omitted the two GT modules, producing two black boxes and invalid counterexamples; attempts 01 and 02 failed at launcher setup. All attempts are retained. An extended 15-minute attempt 05 was interrupted before completion when host free RAM approached 2 GiB, prioritizing the concurrent Runtime placement; it is not a proof result.

Reproduce in the interactive Rocky EDA shell from this worktree: `bash research/vcu118_arch/run_ef2_32lane_formal.sh runs/ef2_32lane_formal_NEW`. The candidate source core is identical to the baseline file with `PAIR_LOOKAHEAD` selected only in the miter. The separate integration candidate has not passed Full Top PPA.

# Thermo5 VCU118 architecture research — working report

Status: **research in progress; no routed PPA, GTY board, or RF signoff**. Base commit: `67d68abb402f9bb2c9a87a43a99f46955acfe9d9`; branch `work/thermo5-vcu118-architecture-research`. The independent worktree preserves the original thermo5 worktree and its uncommitted files. Generated evidence remains under this worktree's ignored `runs/` directory. The accompanying [tradeoff table](data/architecture_tradeoff.csv) distinguishes actual accepted RTL PA captures from scalar models. Values are not interchangeable with radiated measurements.

## Runtime output contract

The runtime backend has EF1 and EF2 four-plane equal-weight outputs, and MASH 1-1 two 64-bit outputs with bipolar weights 1 and 2, giving levels {-3,-1,1,3}. Architecture selection is made with the AXI-Lite mode register after STOP and drain; the existing product top does not implement an integrated physical GTY or complete-frame serializer FIFO. A 64-bit plane accepted each core cycle at nominal 218.75 MHz corresponds to 14.000 Gb/s **conditionally**. The runtime backend accepted and retired 2,048 consecutive words without bubbles for each of EF1, EF2 and MASH; first-word latencies were 3, 2 and 8 cycles, respectively, with correct masks and transaction order in both Icarus and VCS (`runs/runtime_backend_ii_02/simulation.log`, `runs/runtime_backend_ii_vcs_01/simulation.log`). The separate MASH test provides a waveform (`runs/mash_ii_02/stream.vcd`). This finite test does not guarantee an uninterrupted complete system stream for arbitrary AXIS stalls.

Nominal raw throughput, conditional on one accepted word per cycle, is 56 Gb/s across four independent planes for EF1 or EF2, 28 Gb/s across two for MASH 1-1, and a hypothetical 42 Gb/s across three for MASH 1-1-1. These totals do not describe single serial links and do not establish that the corresponding number of GTY lanes has been built or synchronized.

The weighted encoder directed test checks all 64 positions, bit 0 earliest, the I/-Q/-I/Q phase convention, and 1:2 reconstruction (`runs/fs4_rtl_mapping_01/simulation.log`). At a nominal 14 GHz raw sample rate the four-sample sinusoid is 3.5 GHz. The independent analysis of 5,264 real accepted MASH RTL PA words produces digital PSD `runs/fs4_rtl_psd_01/actual_pa_psd.csv`; its nominal in-band range is 3.375–3.625 GHz. This PSD assumes those words are serialized contiguously and is not a measurement of analog RF output.

The existing `rtl/gt/thermo5_raw64_continuous_tx.sv` requires all four valid planes, so its MASH two-plane mask triggers its fault; it also faults when RUN falls before an outstanding valid payload has drained. The directed expected-negative reproducer is in `runs/serializer_contract_01/`. Startup prefill of the existing frontend is not complete-frame prefill. As a research-only candidate, `research/vcu118_arch/thermo5_frame_prefill_tx.sv` implements two banks, complete-frame prefill, a maximum 56-word frame, tagged architecture/config/reset epoch, fixed-rate per-frame output, STOP/drain, and fault checks. `runs/frame_prefill_08/` records normal, back-to-back, STOP/restart, illegal mode switch, overflow, and link-loss tests and VCD. A 5,264-word parameterization passes the same directed tests with counter-pattern data, including 10,528 consecutive output words (`runs/frame_prefill_qam_01/simulation.log`). An independent test replays all 5,264 actual MASH RTL QAM PA words with input bubbles and STOP mid-frame and checks both output planes bit by bit without output bubbles (`runs/prefill_actual_qam_01/simulation.log`). It is not integrated in the product top or PPA cases. The default 56-word configuration would reject the present 5,264-word QAM frame; setting the parameter to at least 5,264 is necessary unless segmentation is validated. Two 5,264-word banks require 2,695,168 data bits before metadata; synthesis resource use is unmeasured. The actual QAM PA replay tests the buffer in isolation, without the live frontend or GTY. It cannot guarantee infinite continuous frames when the source has unbounded stalls; CDC, GT reset/relock and physical lane skew still need design and verification.

## Third-order MASH model

`research/vcu118_arch/mash111_research.py` and independent MATLAB `mash111_scalar.m` are model-only. With Q=32768, D=1-z^-1 and reset residues zero, the fixed-point stage relations are q1=x/Q-D r1/Q, q2=(r1-Q)/Q-D r2/Q, q3=(r2-Q)/Q-D r3/Q. The digital cancellation `y=q1+D*q2+D^2*q3` gives the exact integer identity `Q*y=x-D^3*r3`; it is checked for every I and Q sample. The output levels are {-7,-5,-3,-1,1,3,5,7}, mapped exactly to three bipolar planes weighted 1:2:4. This would require three nominal 14 Gb/s output lanes and a new analog combiner. Relative to MASH 1-1, the architectural estimate is one extra first-order stage (3 versus 2, +50%), one extra 64-bit plane/14 Gb/s serializer lane (3 versus 2, +50%), and second-difference cancellation/history logic. It is not an RTL implementation or measured LUT, FF, DSP, BRAM or power estimate. MATLAB and Python agree on all 168,448 samples of the fixed OFDM input (`runs/mash111_matlab_full_01/matlab.log`).

## VCU118 same-boundary PPA

The four-case script targets `xcvu9p-flga2104-2L-e`, 125 MHz AXIS, 100 MHz AXI-Lite, 218.75 MHz core, centered cubic twice, identity DPD and XPM FIFO. Identity is the reset/benchmark DPD setting; the programmable one-tap coefficient logic remains in each netlist and timing is not case-analyzed to identity, so these are not identity-specialized hardware areas. The three static cases are research proxy tops that constant-select a backend while retaining the common front end and AXI-Lite boundary; they are not deployment-ready static products. The runtime proxy, with dynamic selection, passed the existing runtime switching UVM check for 448 words and six transitions (`runs/ppa_runtime_equiv_01/simulation.log`). No serializer candidate or GTY is included. No user false paths or clock groups are inserted; 0.2 ns I/O budgets are provisional, and unrelated clock timing needs a reviewed CDC/constraint contract. EF1 routing also reports unset `HD.PARTPIN_LOCS` for OOC ports, so port physical delays cannot establish system-level I/O timing. Vivado rounds the requested 4.571428571 ns core period to 4.571 ns, slightly conservative. Power reports, when available, are vectorless estimates, not measured switching power.

The leading synthesized path motivates a separate arithmetic candidate, not integrated into any PPA case: `research/vcu118_arch/centered_cubic_midpoint_candidate.sv` rewrites the fixed Q14 midpoint numerator as `9*(x0+xp1)-(xm1+xp2)`, followed by signed round-away-from-zero and saturation. For W=16, a Z3 integer proof shows the reduced numerator fits 21 signed bits and the rounding expressions are identical; all 2,097,152 reduced 21-bit inputs were independently enumerated. Icarus additionally checks all 65,536 four-bit input tuples and 100,000 16-bit tuples (`runs/cubic_candidate_01/`, `runs/cubic_math_smt_02/`, `runs/cubic_rounding_exhaustive_01/`). The arithmetic has additionally been integrated only in isolated branch `work/thermo5-vcu118-cubic-optimization`, commit `3f88efef965e2d5705adc57d06f530c265af2e82`; XSim, VCS and eight full-runtime QAM streams pass there, and all 36 phase/plane PA capture hashes match the preserved baseline. This is not a whole-module RTL formal proof, a measured timing improvement, or a product replacement. The full 16-bit RTL bit-vector miter timed out at 120 seconds (`runs/cubic_candidate_formal_01/yosys.log`); a separate clocked arithmetic VC Formal attempt returned inconclusive at its 4-minute limit (`../thermo5_vcu118_cubic_optimization/runs/cubic_vcf_01/properties.txt`). A split RTL rounding/saturation miter passed, but its numerator miter timed out (`runs/cubic_split_formal_02/`), so whole RTL formal equivalence remains open.

The isolated optimized EF1 candidate completed synthesis using the identical Tcl hash and device. Baseline versus optimized synthesis is: core-clock WNS -1.823 versus +1.140 ns; LUT 48,098 versus 48,069; FF 49,833 versus 49,836; DSP 670 versus 496; BRAM 6.5 versus 6.5. The optimized overall synthesis WNS is -0.694 ns, associated with an unexpanded cross-clock path; the full cross-clock contract remains unreviewed and no false path is added. Routed baseline versus optimized EF1 gives core WNS -2.797 versus +0.075 ns, core WHS +0.027 versus +0.023 ns and approximate core Fmax 135.722 versus 222.420 MHz. Candidate LUT/FF/DSP/BRAM are 47,053/49,853/496/6.5; vectorless total power 4.815 W versus baseline 5.331 W. The 0.075 ns core margin is small; the new worst core path is `run_sync2` to a FIFO enable and is dominated by routing. Candidate overall WNS -0.363 ns comes from `cfg_mailbox_q` in AXI-Lite to `cfg_pending_core`; the request is synchronized and mailbox held until acknowledgement, but the multi-bit CDC timing contract must be proven and constrained before signoff. Overall WHS is +0.002 ns. No exception was added; OOC clock and port limitations remain. Candidate QAM PA captures match baseline byte for byte.

The current EF2 backend still implements a 32-sample combinational recurrence; `PAIR_LOOKAHEAD` is an experimental, disabled option. A separate branch `work/thermo5-vcu118-ef2-lookahead` at `947f7d4332f2e5f00890219ab3acf3bb713322bd` combines the cubic candidate with the existing pair lookahead; its XSim/VCS regressions and all 36 runtime QAM PA file hashes match baseline. An additional 4,096-cycle VCS miter covers 408 positive clamps, 409 negative clamps, 817 stalls, 616 bubbles, 103 negative ties and reset. VC Formal additionally proves seven assertions and reaches four covers for the two-sample relational harness, with zero black boxes. The proof does not cover the integrated 32-lane implementation, PPA or the whole system. Its current matched EF2 path and feasibility must be measured before choosing an algorithm-preserving architecture change. Old EF2 routed WNS is historical evidence, not a result for this run.

## Exact nominal 14 Gb/s GTY candidate

The GT Wizard accepts 14.000 Gb/s raw 64-bit TX/RX with a nominal 125 MHz reference; it rejects the tested 156.25 MHz reference at that exact rate. The VCU118 QSFP1 candidate uses GTYE4 channels X1Y48/X1Y49, bank 231 and REFCLK0 X1Y12; the board guide identifies the associated programmable Si570 reference. This is a nominal configuration, not proof that the actual board clock has been programmed or meets jitter requirements. [AMD VCU118 user guide](https://docs.amd.com/api/khub/documents/Uoc4S9pQd1uve6kiGiG2kA/content), [GT Wizard product guide](https://docs.amd.com/r/en-US/pg182-gtwizard-ultrascale/Transmitter-Frame).

The vendor digital simulation reports TXUSRCLK2 period 4571.429 ps, both TX reset-done, 256 words or 16,384 serial bits per lane matched bit0-first, and an internal TX-to-RX PMA loopback matching all 16,384 bits per lane. The known training latency is explicitly located before comparing the full sequence; measured inter-lane skew is zero in this simulation (`runs/gty_qsfp_loopback_launcher/console.log`). Hardware refclock programming/measurement, PCB lane assignment and constraints, GTY integration, alignment over resets/PVT, physical eye, combiner and RF EVM/ACLR remain unverified.

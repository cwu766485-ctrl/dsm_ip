The plan's criterion for setting a reset-port-wide false path is not met. The
enumeration does not prove these structures are functionally wrong, but it
proves they are not exclusively reset-synchronizer CLR/PRE loads. No broad
false path, multicycle path, or other exception was added. This is an open
reset/constraint issue and blocks further timing exceptions under the plan.

The preserved AXIS-to-Core detail report also shows two single-bit
synchronizers with `Exception=None`, two XPM Gray-pointer groups with
`Max Delay Datapath Only`, and one XPM reset synchronizer with a scoped false
path. Clock interaction reports `No Common Clock` / `Partial False Path
(unsafe)`. These are CDC disposition items, not reasons to suppress internal
Core paths.

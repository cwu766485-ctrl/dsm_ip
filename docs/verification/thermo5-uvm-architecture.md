# Thermo5 DUT and UVM ownership

The main thermo5 configuration uses `W=16`, centered-cubic x2 interpolation,
one-tap identity DPD, EF2 TIDSM (`TIDSM_ORDER=2`, `STEP=5120`), and
`ENABLE_LOW_POWER_CTRL=0`. The UVM default compiles the generic async FIFO
(`FPGA_USE_XPM_FIFO=0`); the ZU15EG FPGA parent selects XPM. The first-order
TIDSM remains a selectable fallback (`TIDSM_ORDER=1`, `STEP=7168`). This is a
digital raw-word transmitter, not a physically instantiated serializer, PA,
or RF output. The 14-GS/s figure is the serial sample cadence of each plane
(`64 * 218.75 MHz`); the `Fs/4` bit mapping represents a 3.5-GHz digital IF.

## DUT interface contract

| Clock/domain | Port group | Main-chain meaning |
| --- | --- | --- |
| AXI source, 125 MHz | `s_axis_aclk`, active-low `s_axis_aresetn`; `s_axis_tvalid/tready` | One accepted beat has 14 consecutive complex samples. The source holds data and metadata stable under backpressure. |
| AXI source | `s_axis_i_vec`, `s_axis_q_vec` | Two signed 224-bit vectors: 14 lanes * 16 bits, lane 0 earliest. |
| AXI source | `s_axis_tuser_frame_start`, signed 16-bit `s_axis_tuser_frame_gain` | Frame-start/gain metadata travels with the beat. Legal starts align to a 56-sample superframe. The frozen parallel-config SKU has no `TLAST`; the optional AXI-Lite wrapper adds it for graceful packet stop. |
| AXI source status | `s_axis_fifo_full` | FIFO-full observation; not a substitute for `tready`. |
| Core, 218.75 MHz | `core_clk`, active-low `core_aresetn`, `core_enable`; `core_underflow`, `core_protocol_error` | Core run/reset and sticky CDC/protocol diagnostics. The FIFO must prefill before continuous-frame operation. |
| Core DPD configuration | `dpd_active_taps`, six signed 64-bit packed coefficient buses `c1_re/im`, `c3_re/im`, `c5_re/im` | Top-level programmable interface, but this SKU ties active taps to 1 and unity Q2.14 `c1_re=16384`; all other coefficient fields are zero. The memory-DPD RTL is instantiated, not bypassed. Only the least significant 16-bit tap slice is used with `DPD_MAX_TAPS=1`. |
| Core output | `pa_valid[3:0]`, `pa_data[0:3][63:0]`, `pa_ready[3:0]` | Four aligned thermometer code planes. They advance or stall as one word. Each plane is 64 raw bits per core clock; no GT/serializer or physical PA is in this DUT. |

The exact full-frame UVM gate is 32 accepted AXI beats = 448 complex ingress
samples = 56 core words of eight complex samples. Two x2 interpolators make
32 complex samples per core word; `Fs/4` mapping produces 64 ordered real
raw bits per plane. The four planes represent five possible summed levels,
not four independent QAM channels. In the AXI-Lite wrapper only, `TLAST`
marks a packet end and must occur after a positive multiple of 32 accepted
beats; the UVM source monitor checks that marker and covers one-quantum and
multi-quantum packets. A 64-beat packet corresponds to 112 ordered output
words per plane and is checked against a 112-word MATLAB oracle.

## RTL instance chain

```text
tid32_thermo5_axis_frontend_tx
  dsm_axis14_to_core8_cdc          125-MHz async FIFO + 14:8 gearbox
  tid32_thermo5_frontend_tx        218.75-MHz computation
    dsm_frame_gain_vector          frame-wise Q2.14 gain
    dsm_interp_x2_centered_cubic_vector 8 -> 16 complex, half-sample cubic
    dpd_vector_elastic_buffer      word-atomic timing boundary
    dpd_vector16_memory_poly       16-lane identity-configured memory DPD
      dpd_memory_poly              per-lane recurrence and saturation
    dpd_vector_elastic_buffer      word-atomic timing boundary
    dsm_interp_x2_centered_cubic_vector 16 -> 32 complex, half-sample cubic
    tid32_thermo5_fs4_multipa_tx   four offset branches
      tid32_cartesian_ef2_fs4_gt_tx default EF2 TID + Fs/4 raw-word mapping
```

The selected TIDSM implementation is generated by `TIDSM_ORDER`; the
first-order block replaces the EF2 block when the fallback parameter is 1.
Both preserve 32-lane sample chronology and four-plane word alignment.

The canonical RTL is under `rtl/axis/`, `rtl/frontend/`, `rtl/interp/`,
`rtl/dpd/`, and `rtl/tx_bandpass_if/`; the precise compilation set and order
are in `dv/uvm/sim/thermo5_sku_filelist.f`.

## Reference model and UVM checking

Thermo5 has two bit-true vector generators for the frozen identity-DPD SKU:
MATLAB's `matlab/tx_bandpass_if/gen_tid32_thermo5_frontend_bittrue_vectors.m`
and the pure-Python port at
`dv/uvm/refmodel/python/dsm_refmodel/thermo5.py`. Both emit the source I/Q,
frame metadata, and four expected PA-plane `.mem` files. The Python generator
is the Linux route when MATLAB is unavailable. Python-native random vectors
use Python's seeded PRNG, so they are deterministic but do not reproduce
MATLAB's random stream; pass the same source `.mem` files to the Python
generator when doing a sample-by-sample cross-check.

The source sequence reads source vectors; the scoreboard independently reads
the expected source and PA files and compares accepted transactions. The
`.mem` outputs are the oracle and the scoreboard is a comparator. The Python
thermo5 model covers frame gain, both x2 interpolation stages, identity DPD,
and four-plane TID. Its optional memory-polynomial path models signed Q2.14
coefficients, temporal taps, RTL arithmetic shifts, and output saturation. The
directed AXI-Lite nonlinear test checks a two-tap image with nonzero cubic terms
against all four output planes. This is a verification image, not a calibrated
DPD solution. Nonlinear PA behavior and RF effects require separate models.

Centered-cubic UVM checks now cover a 32-beat short packet and two back-to-back
32-beat packets (64 beats total), with frame-tail reconstruction and exact
four-plane output comparison. The low-power test requests STOP in the middle
of a packet, verifies ingress continues through accepted TLAST, and checks
that all output drains before the power state returns to IDLE.

The VCS thermo5 UVM target uses the portable generic FIFO. Vendor-XPM FIFO
full-chain XSim evidence is separate; neither target verifies physical GT,
board-level four-way serialization, analog PA, or RF EVM.

For fixed stimulus, the RTL produces deterministic output words; fixed-point
quantization and interpolation differences are deterministic distortion, not
random noise injected by the digital design. Separate Python link screens
model bit errors on the four TID planes as digital faults, then model DPA and
output-network distortion followed by kTB/NF analog noise. These screens are
sensitivity tools outside the DUT and require measured link parameters before
their absolute EVM can be treated as a hardware prediction.

### Raw-plane receiver audit

`dv/uvm/refmodel/python/benchmark_thermo5_tid_receiver.py` separately audits
the temporal meaning of the frozen RTL2 output and reconstructs its serialized
planes through Fs/4 DDC, filtering, and 256-QAM OFDM demodulation. The RTL2
interpolator emits exact `x[n]` at the even phase and `(x[n]+x[n-1])/2` at the
following odd phase. The latter is a previous-midpoint estimate if assigned
the timestamp `n+0.5`; a centered cubic needs future samples to estimate the
half-sample at that timestamp.

For each of seeds 101/307/503, the Python plane stream had zero mismatches
against four independent scalar EFM recurrences across 1,335,296 branch and
component samples. At a shared 0.10 RMS drive and peak limit 0.35, the
eight-symbol, 250-MHz receiver screen measured centered-cubic digital EVM
3.273% / SNDR 29.702 dB on average; the frozen RTL2 measured 20.827% /
13.628 dB. The nominal illustrative DPA/output/noise chain gave cubic
3.370% / 29.447 dB; the stress chain gave 3.685% / 28.671 dB. Detailed runs
are in `runs/thermo5_tid_receiver_20261024/summary.json`.

Support analysis of both centered stages gives a 2.25-source-sample maximum
future dependency, rounded to three input samples for a causal stream. With
eight input lanes this crosses one input transaction. The optional RTL path
now implements that lookahead with two elastic centered-cubic x2 stages. At
frame end, stage 1 processes a synthetic zero-source vector and tags the
interpolated result; stage 2 uses that vector to reconstruct the final real
output and then drops it. This keeps the PA output count equal to the input
frame count at 4x interpolation.

The main default selects centered cubic (`INTERP_CENTERED_CUBIC=1`); set the
parameter to `0` to select the causal polyphase fallback. The parallel-config AXI wrapper carries
`s_axis_tlast` through the CDC/gearbox, frame-gain pipeline, and DPD metadata.
Frame ends must align to a complete 56-sample gearbox group (four 14-lane AXI
beats). The centered-cubic UVM regression checks four-plane output with
backpressure; the current 56-word generic and AXI-Lite regressions pass with
EF2/STEP=5120. The AXI-Lite suite covers configuration, commit, STOP, reset,
and packet-boundary cases. Short and two-quantum packet bit-true cases pass.
VCS behavioral serializer loopback passes 56 words / 3,584 bits per PA path.
Valid `TLAST` frame ends must still align to a complete 56-sample gearbox
group. XSim, XPM requalification, GT Wizard/TXP simulation, and FPGA
resource/timing were not run on Linux; these remain open.

## Verification architecture

```text
tests/thermo5         test intent and pass criteria
  sequences/thermo5   MATLAB-vector source scenario
    agent/axis         AXI source item -> sequencer -> driver; independent
                       accepted-beat monitor -> analysis port
    agent/rf           passive four-plane output monitor -> analysis port
  env/thermo5         control BFM, config, coverage, reset-epoch scoreboard
  tb                  clocks, interface, frozen DUT parameters and pins
  sim                 target filelist, VCS/regression and URG entry points
```

An agent-local sequence such as `agent/axis/dsm_axis_sequences.svh` models
one reusable protocol endpoint. A scenario in `sequences/axi_ip/` coordinates
several agents; `sequences/thermo5/` owns a project-specific vector stream.
This is a responsibility distinction, not two copies of the same stimulus.
The active AXI-IP and thermo5 tops remain separate packages and filelists.

This layout follows Accellera UVM 1.2 User's Guide sections 3.8-3.10 (agent,
environment and scenario creation) and 4.7-4.10 (virtual sequences,
scoreboards and coverage). The guide specifies component responsibilities,
not a mandatory filesystem naming convention:
https://www.accellera.org/images/downloads/standards/uvm/uvm_users_guide_1.2.pdf

The test-to-check and coverage boundary is recorded separately in
`docs/verification/thermo5-uvm-coverage.md`.

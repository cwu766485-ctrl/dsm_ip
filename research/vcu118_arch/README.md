# Reproduce the VCU118 architecture study

Run from the root of this research worktree. Each shown destination must be new. The original input and full-chain captures are preserved in the neighboring pre-existing `runs/thermo5_runtime_product/runs/runtime_qam281001` directory; they are deliberately not regenerated or overwritten here. This study requires Python/NumPy/SciPy, Icarus, Vivado 2026.1, and optionally MATLAB and VCS. Refer to the report for evidence boundaries.

```bash
# Recreate the same seed, RMS 0.09, 8-symbol stimulus and actual XPM RTL
# capture from canonical sources; each destination must be new.
python3 dv/uvm/refmodel/python/thermo5_runtime_qam.py prepare \
  --out runs/repro_input_NEW --seed 281001 --symbols 8
python3 dv/uvm/refmodel/python/generate_thermo5_runtime_vectors.py \
  --input-dir runs/repro_input_NEW/input --output-dir runs/repro_vectors_NEW \
  --words 5264 --seed 281001
python3 dv/uvm/sim/run_thermo5_runtime_xsim.py \
  --out runs/repro_capture_NEW --vectors runs/repro_vectors_NEW \
  --words 5264 --beats 3008 --seed 281001 --xpm
```

On the Windows host, run the GT Wizard digital serial loopback with a **new** output directory (the script refuses an existing one):

```powershell
& 'D:\AMDDesignTools\2026.1\Vivado\bin\vivado.bat' -mode batch `
  -source research/vcu118_arch/sim_gty14_qsfp_clock_loopback.tcl `
  -tclargs runs/repro_gty_NEW
```

Require the explicit `GTY_TX_SERIAL_BITTRUE_PASS`, `GTY_RX_LOOPBACK_BITTRUE_PASS`, and `GTY_TXUSRCLK2_PASS` messages, not just Tcl completion. A vendor simulation is not a physical transceiver test. For post-route Fmax, run `report_routed.tcl` on each completed routed DCP into a fresh directory; evaluate clock-interaction and I/O assumptions before interpreting its core-only result.
